# Phase 1 — Visual System + Shell Design

**Date:** 2026-10-03 · Part of the v10 roadmap (`2026-10-03-careos-v10-redesign-roadmap.md`)
**Reference artboards** (local copy in `docs/design/careos-v10/`): `Main` (kit), `TopBar`, `Dock`, `AppIcon`, `Desktop`, `Launcher`, `ControlCenter`, `WifiMenu`, `Widgets`, and the window chrome of `Terminal` / `SettingsLook`.

## Goal

Every surface of the desktop shell matches the canvas, in dark and light. A shared token + component kit means phases 2 and 3 only lay out screens on top of it, and don't re-invent styling.

## Rules
- **Real data or hide.** Elements without a data source in CareOS are omitted (weather, battery in a VM, Bluetooth, media, audio slider without an audio device). Nothing shows invented values.
- **Kit only.** Shell code draws through `gui/ui.h` and tokens; no raw hex colours outside `gui/theme.c`.
- Integer / Q16 math only (kernel built `-mno-sse`). No allocation in per-frame paths.

## 2. Font roles — `gui/font.c`, `gui/fonts/`
- `font_role_t { FONT_ROLE_UI, FONT_ROLE_DISPLAY, FONT_ROLE_MONO }`. Each role has its own family: UI = **Figtree** (regular + bold), Display = **Bricolage Grotesque** (bold + extra-bold), Mono = **JetBrains Mono** (existing).
- Glyph tables are generated by `tools/gen-font.py` from the OFL TTFs, which are downloaded from the google/fonts GitHub repo and committed under `fonts/` with their OFL licence files.
  - Sizes: UI 11/13/15/17/20.
  - Display 22/28/34/52/64; Display needs a separate set of size slots, `FONT_DISPLAY_SM..XL`.
- New calls:
  - `gfx_str_role(x, y, s, fg, role, size, weight)`
  - `gfx_str_role_width(...)`
  - The existing `gfx_str_ex` = UI role, regular weight.
- The user's font-family setting keeps applying to the UI role only.
- `gfx_str_clipped` and every width helper use true per-glyph advances (proportional faces), with ellipsis on overflow.

## 3. App icons — `tools/gen-careos-icons.py`, icon archive

- Rasterized with anti-aliasing at 24, 32, 40, 44, 52, 56, 64, 76, 96, 128 into the existing icon archive (ARGB, QOI-packed if the archive supports it).

- `gfx_draw_icon(app, x, y, size)` picks the exact size if present, otherwise the next larger one, scaled down with box filtering.
- `ui_app_icon(key, x, y, size)` also draws the runtime drop shadow `0 4 14 rgba(8,10,30,.22)`.

## 6. Real blur with a backdrop cache — `gui/ui.c`, `gui/gfx.c`
- `ui_glass` blurs what is *behind* the panel at draw time, through a **backdrop cache** keyed by a panel id: {rect, radius, blur, generation, half-res blurred pixels}. Up to 24 entries, allocated when a panel first appears and freed when it disappears.
- **Generation tracking:**
  - The compositor keeps a coarse damage grid (64×64 px cells) of a monotonically increasing counter. Anything drawn *below* a panel's layer that changes pixels bumps the cells it covers: wallpaper, desktop widgets, windows below, a theme or scale change.
  - A panel re-blurs only if any cell under its rect is newer than its cached generation. Otherwise it blits the cache, then tint, hairline and content.
- **Blur:** downsample the region ×2 (box), run 3 passes of separable box blur at radius `blur/2/3` each (≈ Gaussian σ), upsample bilinearly and composite with the rounded mask. Rows/bands are split through `wp_parallel_for` (phase 0; inline on one core).
- **Windows:**
  - Window bodies are 92 % opaque in dark; their glass shows only at the edges.
  - A window being dragged or resized uses tint-only glass, and is re-blurred 1 frame after it settles.
  - Windows above other windows blur the composed scene below them, which takes a snapshot of the layer under the window.
- **Guard:** if 3 consecutive frames exceed 33 ms, all glass switches to tint-only until 1 s with no frame over 20 ms. Settings › Appearance "Reduce transparency" (phase 3 UI; the setting key lands here) forces tint-only.

## 10. Desktop — `gui/gui.c` desktop layer, `gui/widgets.c`
- **Shortcut column** (left 28, top 68, gap 14): Home (files), Care scripts, Wallpapers (photos), Trash. 96 px buttons, 56 icons, label UI 13 semibold with a text shadow.
- **Hero** (left 260, top 200, width 700, positions scaled to the resolution):
  - weekday + date (UI 18 medium, ink2)
  - "Good morning|afternoon|evening, \<user display name\>." (Display 64 extra-bold; the greeting by local hour: 5–12, 12–18, else evening)
  - the 60 px glass search bar with a search glyph, placeholder "Search apps, files, settings and the web" and Ctrl Space key caps; clicking it or pressing Ctrl+Space opens the launcher with the query
  - up to 3 **resume chips** from real state: last-closed app with a session ("Resume in Terminal"), most recent file from the VFS recent list, "N updates ready" only if `carepkg` reports updates
  - The hero hides when windows cover it (any maximized window) and on screens shorter than 720 px.
- **Right column widgets** (right 24, top 64, width 300, gap 14; existing widget framework, restyled):
  - Clock card: weekday in care_soft caps, time Display 52, full date. No weather.
  - Calendar: month name in Display 17, a 7-column grid, today as a coral filled circle.
  - System: CPU / Memory / Disk real percentages with 6 px bars in calm / care / success, header "All good" (success) or "Busy" (warning above 85 %).
- **Sticky note** (yellow `#FFD36B`, ink `#3A2600`, −2° look approximated by a drop shadow; rotation is not drawn): user-editable text saved to `~/.config/sticky.txt`. Starts empty with the placeholder "Write something…".
- **To-do widget** (from the Widgets artboard): items in `~/.config/todo.txt`, checkbox toggles.
- Widget gallery (add/remove) lists only these real widgets.

## 11. Launcher — `gui/launcher.c` (full screen)
- The backdrop is the current screen, blurred 30 and tinted `#070A16` @ 55 %. The light theme tints white @ 55 %.
- Layout (centred, width 1000):
  - search field 560×52, radius 18, white 10 % fill, white 16 % hairline, placeholder "Type to find an app"
  - category chips: All apps (selected = light pill), Make, System, Internet, Games
  - 7-column grid of 76 px icons + labels (UI 14 semibold), row gap 26; hover = white 8 % tile
  - page dots
- App categories are a static table per `app_id_t`.
- Typing filters by substring (case-insensitive) over the name and keywords. Arrows move the selection, Enter launches, Esc closes, Ctrl+Space toggles.

## Error handling
- A missing font table or icon size falls back to the nearest available one; a missing wallpaper falls back to the procedural tokens gradient.
- Blur cache allocation failure → tint-only for that panel, logged once.

## Testing
- **Host tests:**
  - token tables (contrast check: ink on ground ≥ 7:1, ink2 ≥ 4.5:1, on_care ≥ 4.5:1)
  - font-role metrics and proportional width
  - icon size selection
  - damage-grid / generation invalidation
  - launcher filter + keyboard navigation model
  - greeting by hour
  - dock indicator model
- **QEMU QA** at 1440×900 and 1920×1080, dark + light: desktop, launcher (empty + filtered), Control Center + notifications, network popover, widget gallery, a Terminal window (chrome), menu bar with an app menu open. Screenshots are saved next to each artboard export for side-by-side review.
- **Perf:**
  - `perf bench` static desktop ≥ the post-perf-plan baseline
  - window drag over glass ≥ 30 fps on the 4-core VM
  - the guard must never engage on a static desktop
